# MAKCM 当前交接

## 系统边界

- Windows 数据面连接左板 USB Device；可信维护 Linux 通过左板 CH343 执行 OTA。
  左板经板间 UART 转发目标为 Right 的 MKOT 帧。
- 左板是 ESP-IDF 5.5.4 USB Device；右板是 ESP-IDF 5.5.4 原生工程中的 USB Host，
  Arduino API 来自锁定的 Arduino-ESP32 3.3.10 managed component。
- 普通运行面与 OTA 维护面互斥；无法证明安全状态时不恢复 USB 透传。

## OTA 当前事实

- 协议状态仅为 `Idle`、`Receiving`、`Prepared`、`PendingConfirm`。
- 唯一状态载荷为严格 232-byte Status V2。
- `tools/update_proxy_pair.py` 是唯一部署编排入口。
- 更新顺序是 Right prepare、activate、confirm 并回到健康 `Idle`，随后才对 Left 执行同一完整流程。
- 左板不保存或推断双板事务状态；主机只依据两板当前 Status V2 和已验签包做决定。
- 构建产物为 `MAKCM_ESP32s3_HID_Mouse_Right/build/makcm_right_idf.bin` 与
  `MAKCM_ESP32s3_Device_Mouse_Left_IDF/build/makcm_left_idf.bin`。
- `tools/sign_pair_release.py` 是唯一 pair release 签名入口，生产私钥只存在于可信 Linux 签名机。

完整构建、签名、部署和验收步骤见 `docs/OTA_HANDOFF_20260806.md`。

```powershell
python -m py_compile tools/sign_pair_release.py tools/makcm_ota_tool.py tools/update_proxy_pair.py
python -m unittest tests.test_makcm_ota_tool tests.test_update_proxy_pair tests.test_right_ota_bootstrap

idf.py -C MAKCM_ESP32s3_HID_Mouse_Right build

```

离线验证通过不代表发布完成。签名机往返验签、真实 CH343 单入口双板更新、两板启动确认、
右板 USB Host 恢复和左板 USB Device 恢复必须在目标硬件上留证。
